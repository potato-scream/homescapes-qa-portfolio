## Preconditions
- Homescapes is installed and launched
- Player has at least one active level available
- A second device or person is available to trigger an incoming call
- Lives are available (at least 1)

## Test Steps

| Step | Action | Expected Result | Actual Result | Status |
|------|--------|----------------|---------------|--------|
| 1 | Launch Homescapes and open any match-3 level | Level loads, move counter shows full count | Level loaded correctly | Pass |
| 2 | Make 3-5 moves on the board | Tiles swap and match, move counter decrements | Tiles moved and matched correctly | Pass |
| 3 | Note the current board state and remaining moves | Board layout and move count are recorded | Board state recorded | Pass |
| 4 | Trigger an incoming mobile network call | Call screen appears, game moves to background | Call screen appeared, game backgrounded | Pass |
| 5 | Answer or decline the call, then end it | Call ends normally | Call ended normally | Pass |
| 6 | Return to Homescapes and compare board state with Step 3 | Board layout and move count match state from Step 3 | Board state and move count preserved, no lives deducted | Pass |
| 7 | Repeat steps 1-6 using an incoming Telegram call | Same result - level progress preserved after Telegram call | Board state and move count preserved, no lives deducted | Pass |

## Result
Bug could not be reproduced on iPhone 15 Pro, iOS 17.4, Homescapes v6.x.
Tested with two interruption types: incoming mobile network call and incoming Telegram call.
Level progress was fully preserved in all runs. No lives were deducted.
The issue described in BUG-001 may have been fixed in a recent game update.

## Notes
- Each scenario tested 3 times, consistent result across all runs
- iOS screen recording stops automatically when an incoming call is received,
  so video evidence could not be captured for this test case
- Official Playrix Help Center still lists this as a known issue as of 2026-04-03
- Recommend re-testing on Android and on older iOS versions"
